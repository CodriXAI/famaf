=== EJERCICIO 3 - PRACTICO 3 S.O ===

Considere los procesos:

----------------------------------------------------------------------------------------

PRE : {cont ^ x = 1 ^ y = 2}
Con cont en True.

P0:
    while(cont && x < 20){
        x = x * y;
    }

P1:
    y = y + 2;
    cont = false;

POST: {¬cont ^ x = ? ^ y = ?}

----------------------------------------------------------------------------------------

(a): Calcule los posibles valores finales de x e y.

(b): Si en P1 se cambia la instrucción y = y + 2; por y = y + 1; y = y + 1; en dos lı́neas 
distintas. ¿Cambia esto los posibles valores finales? Justifique.


(a):
    Analizando, tenemos en el P0 que puede terminar si cont se hace false o 
    si x supera a 20. Dentro del bucle tenemos un multiplicador que guarda en x
    la multiplicación de x por y.

    Luego en el P1 tenemos una suma y = y + 2
    Duda en P1 sobre si cont = false es atómica. 
    SI, en este contexto si es atómica. Simplemente se guarda en el registro donde 
    se ubica cont el valor false.

    Por ende:
        Si observamos bien, para que finalice este programa (POST) se debe dar la 
        condición ¬cont, eso implica que este sea false y para eso el P1 debe en algún
        momento ejecutar cont = false, para que ello suceda, y por orden de ejecución 
        en el sistema operativo, se debe ejecutar y = y + 2 completamente. Luego como 
        cont es atómica y no puede ser interrumpida, cont se hace falsa y 
        finaliza el programa. Pues si vuelve a P0 y quiere volver a entrar en 
        el while se niega la condición y sale.
        Por lo tanto la POST va quedando así:

            POST : {¬cont ^ x = ? ^ y = 4}

        Ahora falta saber los casos para los valores de X, los cuáles pueden variar por 
        las siguientes razones:

            * Caso 1: P0 es interrumpido por P1 antes del producto:
                Luego P1 se ejecuta normalmente y termina la guarda, terminando como:

              POST : {¬cont ^ x = 1 ^ y = 4}

            * Caso 2: P0 efectúa un producto, queda en x = 2, Y luego es interrumpido 
            por P1, donde se efectua con normalidad y termina la ejecución, terminando 
            como:

              POST : {¬cont ^ x = 2 ^ y = 4}

            Así sucesivamente con: X = {1,2,4,8,16,32}

            Porque luego si quisiera volver a efectuar P0 con X = 32, ya no sería posible 
            y saldría del bucle, luego P1 se ejecutaría y haría y = 4 y cont = false.

                POST : {¬cont ^ x = {1,2,4,8,16,32} ^ y = 4}
            
            * Último Caso: P0 se ejecuta hasta X = 16, donde y = y + 2; es interrumpido 
            constantemente, luego cuando X llega a 16, interrumpe P1, y = y + 2 se 
            efectua, teniendo y = 4, luego antes de que se ejecute cont = false, se 
            interrumpe y vuelve a P0, como X < 20, ejecuta el producto, quedando con 
            X = 16 * 4 = 64.
            
            
        
        Finalmente la POST queda:

            POST: {¬cont ^ x = {1,2,4,8,16,32,64} ^ y = 4}

(b):
    Ahora supongamos que:
        PRE : {cont ^ x = 1 ^ y = 2}
        Con cont en True.

        P0:
            while(cont && x < 20){
                x = x * y;
            }

        P1:
            y = y + 1;
            y = y + 1;
            cont = false;

        POST: {¬cont ^ x = ? ^ y = ?}
    
    Aquí la cosa cambia un poco para X mas que nada, porque tenemos unos casos 
    intermedios.

    Tenemos los casos donde:
        * Y = 2, Y = 3 e Y = 4.
        * Por esos casos es que va a existir un umbral mayor de valores de X 
        * No olvidar postcondicion y guarda del while.
    
    Para empezar, y para respetar la POST, Y = 4 y cont negada van a ser necesarios.

    Inevitablemente para que cont = false, Y se tiene que sumar 1 dos veces, por ende 
    quedará en Y = 4 nuevamente.

    Para X se vienen las cuentitas:

        * Valor de la PRE:
            X = {1}
        * Puede ocurrir todo el umbral de multiplicaciones con Y = 2, osea:
            X = {2,4,8,16,32}

        * Y también el umbral donde se multiplica por Y = 2 hasta que X = 16 y luego que 
        se sumen 2 veces Y + 1, para que se multiplique 16 * 4, dando lugar a:
            X = {64}

        * Ahora con el nuevo estado intermedio Y = 3 veamos cuales escenarios podrían 
        ocurrir:
            1 * 3 = 3   -> Cumple X < 20
            2 * 3 = 6   -> Cumple X < 20
            4 * 3 = 12  -> Cumple X < 20
            8 * 3 = 24  -> NO Cumple X < 20
            16 * 3 = 48 -> NO Cumple X < 20

            X = {3,6,12,24,48}

            Estos los base. Luego se generarían nuevos estados combinados tales como:

            3 * 3 = 9    -> Cumple X < 20
            6 * 3 = 18   -> Cumple X < 20
            12 * 3 = 36  -> NO Cumple X < 20

            X = {9,18,36}

            Y nuevamente:
            9 * 3 = 27   -> NO Cumple X < 20
            18 * 3 = 54  -> NO Cumple X < 20

            X = {27,54}

            Y ahi ya no hay más casos que cubrir (que respeten X < 20)

        Por ahora tendríamos entonces unificando: 
            
            X = {1,2,3,4,6,8,9,12,16,18,24,27,32,36,48,54,64}

    La justificación del por qué ocurre esto es por la no atomicidad de ambos 
    incrementos y = y + 1; e y = y + 1; presentes, como pueden ser interrumpidos 
    en la mitad, antes o después, dan lugar a más combinaciones de valores posibles de
    X.

    Finalmente la POST quedaría:
        POST: {¬cont ^ x = {1,2,3,4,6,8,9,12,16,18,24,27,32,36,48,54,64} ^ y = 4}
