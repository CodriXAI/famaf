Indique que hacen estos programas.

Programa 1:

int main(int argc, char ** argv) {
    if (0<--argc) {
        argv[argc] = NULL;
        execvp(argv[0], argv);
    }
    return 0;
}

Análisis:

    *Primeramente que chucha significa 0 <--argc
        En realidad se refiere a preguntarse si 0 < --argc, es decir, argc restarle 1 y compararlo 
        si es mayor a 0

    *Recordemos sobre argc = argument counter:
        Cuando tenemos un proceso, el argc tiene al menos un argumento, que es el nombre del proceso
        ./program arg1 arg2. => argc = 3

        Luego, como el mínimo valor que puede tener argc es 1 (al menos debe tener el nombre)
        Al hacer --argc en este caso queda como 0. Entonces, cuanto nos preguntamos 0 < --argc
        Quiere decir: "¿El programa tiene al menos algun argumento? (Aparte del nombre)"
        Equivalentemente nos podemos preguntar if(argc >= 2) (nombre + 1 argumento al menos)
        
        En caso si lo sea, lo que suele pasar es que accede al arreglo de cadenas argv
        que tiene el formato {"name", "arg1", ....., NULL}
        
        Y cambia lo que sería el último valor del arreglo (contando que empieza desde 0) por NULL.
        En palabras simples, cambia el último argumento por NULL. Resultando en ejecutar el mismo
        programa, pero con un argumento menos. Nótese lo siguiente:

        ls -l
        argc = 2
        argv = {"ls", "-l", NULL} => #argv = argc + 1 = 3 
        0 < --argc => 0 < 2-1 => 0 < 1 => true (ahora argc vale 1)
        argv[argc] = NULL => argv[1] == NULL (se cambia "-l" por NULL)
        Luego:
        argv = {"ls", NULL, NULL}.
        Cuando se llame al execv solo ejecutará ls sin su último argumento.




Programa 2:

int main(int argc, char ** argv) {
    if (argc<=1)
        return 0;
    int rc = fork();
    if (rc<0)
        return -1;
    else if (0==rc)
        return 0;
    else {
        argv[argc-1] = NULL;
        execvp(argv[0], argv);
    }
}

Análisis:

    *Tenemos varias condiciones:
        argc <= 1 --> ¿Hay como mucho un argumento aparte del nombre?:
            Si es correcto, se acaba el programa, aparentemente es lo que debería ocurrir.
        
        Luego hacemos una bifurcación fork y la guardamos en una variable rc.
        
        Si no se ejecutó bien el fork, (rc < 0) salimos con error del programa.

        Si estamos en el proceso hijo (rc == 0) entonces volvemos con normalidad

    *Acerca de la última condición (proceso padre):
        Podemos notar que argv[argc - 1] = NULL, osea, a diferencia del primer programa, vemos que
        Solo en el proceso padre se resta un argumento al proceso y lo ejecuta.

    *Ejemplo visual:
        ls -l
        argc = 2
        argv = {"ls", "-l", NULL} => #argv = #argc + 1 => 2 + 1 => 3 
        
        Pasa el primer if:
            Devuelve 0
        
        Se realiza el fork,
        
        En el proceso hijo:
            Devuelve 0

        En el proceso padre en específico:
            argv[argc - 1] = NULL
            argv[2 - 1] = NULL
            argv[1] = NULL
            => argv = {"ls", NULL, NULL}
        
            En el excev, hace el ls en el proceso padre sin argumentos
